## Concrete work possible without hardware

1. Acquire a bounded metadata-first DeepFashion-MultiModal subset through its official links, recording exact terms, hashes and successful files. Join image, lower-garment fabric, skirt parsing and visibility records. Inspect enough originals to verify annotation registration and full waistband-to-hem coverage. Do not infer successful acquisition from the published links.
2. Resolve original split membership and repeated garment/product identities before constructing a project split. Preserve official test/validation restrictions and quarantine components spanning protected boundaries. Adjacent photos, source listings, masks, patches and augmentations of one garment stay together. Counts must distinguish files from verified independent garments.
3. Produce an explicit appearance-label mapping with evidence and human review. Exclude invisible/NA/ambiguous lower garments. Never equate a visually annotated cotton class with pure cotton or a blend percentage. A class vocabulary assembled from different annotation axes requires a documented mapping, not a silent merge.
4. Freeze a manifest and split hash, then train an appearance pilot on full-skirt frames and same-frame native crops. Compare whole-skirt versus native-patch performance, report per-class precision/recall, abstention coverage and errors by source. Select parameters using development validation only. Export and compare desktop predictions before any deployment claim.
5. Keep the model out of automatic release until the model card records this source-domain limitation. Existing image analysis and replay infrastructure can test software integration without recording camera images.

Metadata intake below is completed; image acquisition, label review and training remain outstanding. No camera is necessary for that source-domain experiment. No publisher messages, signatures on behalf of the user, installations or project label/split changes were made.

## Evidence that remains unavailable

Appearance-only annotations cannot supply verified fibre percentages. Composition evaluation needs linked tags, supplier records or a separate verified material source. Performance on the user's worn, hanging, mannequin and held skirts still needs representative evidence; a human-image dataset alone does not validate all four presentations. Actual full-view resolution, blur tolerance and Raspberry Pi latency still need the real capture/device setup. More close-up texture photos cannot substitute for those checks.

## October 10: public archive access verified, partition quota encountered

The image archive is accessible. Following its normal public download confirmation form returned HTTP **206 Partial Content** for two separate 65,536-byte ranges. The exact total reported by both range responses is **6,822,188,210 bytes**. The first range has ZIP magic; the final range contains a valid ZIP64 end record with **44,097 archive entries** and a **6,036,814-byte central directory at offset 6,816,151,298**. Entry count is archive structure, not verified image count. Only 131,072 archive bytes were retained; no complete archive, decoded image or training sample was acquired. The earlier virus-scan warning was a confirmation step, not an access blocker. No account, authentication, publisher message or installation was used.

[Follow-up evidence](../records/review/2026-10-10-fabric-followup.json) records the exact range hashes and durable public source URLs. Temporary download confirmation fields and redirect URLs were not persisted. This makes a bounded ZIP64 member downloader feasible: fetch the central directory, validate its bounds and member names, then fetch only selected compressed members with size and CRC checks. This downloader has **not** been implemented or run; archive accessibility does not establish valid images, labels, identities or partitions.
